TAILWIND CSS - RUEDA NOCTURNA

Instalé `tailwindcss` y `@tailwindcss/cli` dentro de `nocturna/`. El archivo `src/input.css` importa Tailwind y el comando `npm run dev` ejecuta la CLI con `--watch` para generar `src/output.css`.

Revisé el CSS generado: encontré `.bg-slate-950`, que sí se usa en los botones y en el fondo de la página. No encontré `.bg-pink-500`, porque no se usa en el HTML. Tailwind analiza las clases de los archivos fuente y genera solo las utilidades que detecta, manteniendo el CSS publicado más pequeño.

El CSS generado se conserva en el repositorio para que la página funcione en GitHub Pages, donde no se ejecuta la CLI. `nocturna/.gitignore` excluye `node_modules/`.


KIT DE COMPONENTES - RUEDA NOCTURNA

Reglas del kit compartidas por botones, cards, alertas y campos:

- Bordes redondeados: `rounded-xl` (12 px) para todos los componentes y controles.
- Espaciado: escala Tailwind en incrementos de 4 px; se usan `space-y-2/3/4/5/6` y `p-3/4/5` según la densidad.
- Colores base: `slate-950` para el fondo, `slate-900` para superficies, blanco para títulos y `slate-300/400` para texto secundario.
- Acento y estados: amarillo para la acción principal y el foco; celeste, verde y ámbar distinguen información, éxito y advertencia. Los niveles conservan texto explícito además del color.
- Interacción: hover cambia fondo o borde y aumenta la sombra sin modificar las dimensiones; focus usa un anillo de 4 px visible.

La página de componentes comparte `nocturna/src/output.css` con las rutas. La alerta de éxito usa `role="status"` y `aria-live="polite"` para anunciar el mensaje sin interrumpir al lector de pantalla.


LANDING DE RUEDA NOCTURNA

El encabezado, cada sección principal y el pie usan el mismo contenedor centrado `w-full max-w-6xl mx-auto px-4`, con más relleno lateral en pantallas mayores.

Distribución de contenido: las tres rutas usan Grid porque son elementos repetidos en dos dimensiones y deben alinearse en tres columnas en escritorio; en móvil pasan a una columna y en tablet a dos. Los cuatro pasos de «¿Cómo funciona?» también usan Grid: permite mostrar cuatro columnas equivalentes en escritorio y reorganizarlas en dos y una columna según el ancho.

El encabezado usa Flexbox para alinear marca, navegación y acción en un eje horizontal, y el pie usa Flexbox para organizar sus tres bloques en escritorio y apilarlos en móvil.

Se crearon solo tres clases propias con `@layer components` y `@apply`: `.button-primary`, `.button-secondary` y `.button-outline`. La primaria aparece seis veces en la landing y dos en la galería. Las cards permanecen en HTML como marcado visible del kit para conservar su estructura y datos.

Las clases se ordenaron por layout, espaciado, tipografía, color/estilo y variantes. El script `build` añade `--minify`; el artefacto compartido de nocturna (`src/output.css`) quedó en 27,637 B.

Medición de los recursos cargados por `index.html` v2.0:

| Framework / recurso | Tamaño del recurso | Payload Brotli (sin headers) |
| --- | ---: | ---: |
| Tailwind CSS de nocturna, minificado | 27,637 B | No medido en hosting |
| Bootstrap 5.3.8 CSS | 232,111 B | 33,048 B |
| Bootstrap 6.0.0-alpha.1 bundle JS | 219,860 B | 61,153 B |
| Bootstrap CSS + JS | 451,971 B | 94,201 B |

El navegador confirmó las dos solicitudes Bootstrap. La API Resource Timing mostró `transferSize=0` porque jsDelivr no expone `Timing-Allow-Origin`; para no reportar ese cero como tamaño real, se descargaron las mismas URLs HTTPS y se midieron el cuerpo descomprimido y la carga Brotli. Bootstrap v2.0, además, carga CSS 5.3.8 junto con un bundle JS 6.0 alpha.

El tamaño Tailwind corresponde al artefacto CSS local; los estilos y archivos de fuente servidos por Google Fonts son solicitudes separadas y no están incluidos en esos 27,637 B. Los bytes Brotli reportados cuentan el payload comprimido, no los headers HTTP.

| Criterio | Bootstrap en v2.0 | Tailwind en nocturna |
| --- | --- | --- |
| Curva de aprendizaje | Arranque rápido con componentes y convenciones listas; su grilla estándar resulta familiar. | Requiere aprender y leer utilidades; las listas largas se vuelven ruidosas si se repiten, por eso extrajimos los botones con moderación. |
| Personalización | La identidad de v2.0 termina en estilos inline repetidos y selectores propios. | `@theme` concentra paleta y fuentes; variantes responsive/dark y tres componentes `@apply` ajustan la campaña sin otro framework. |
| Tamaño final medido | 232,111 B CSS + 219,860 B JS sin comprimir; 94,201 B transferidos con Brotli. | 27,637 B de CSS minificado para nocturna; no necesita JavaScript de framework para este diseño estático. |
| Casos de uso | Prototipos rápidos y páginas que necesitan componentes Bootstrap convencionales. | Experiencias con identidad visual propia, estados responsive/dark y control del CSS enviado. |

Recomendación: construir la próxima versión de Rueda Libre en Tailwind y migrar por páginas, sin cargar Bootstrap y Tailwind juntos en cada página. En esta experiencia la marca, el dark mode y los breakpoints se resolvieron desde tokens/utilidades, y el CSS final de nocturna es menor que el CSS Bootstrap por sí solo; el coste es una curva inicial mayor y HTML más verboso, mitigado aquí con tres variantes de botón.
